# 念山AI（Nianshan AI）

**本地运行的 AI 歌声工作台** —— 双引擎，无需云端，音频不出本机。

**中文** | [English](README.en.md)

| 引擎 | 能力 | 一句话说明 |
|---|---|---|
| **音色转换**（Seed-VC）| 把一首歌/一段人声换成指定音色 | 零样本：给 10 秒参考音频即可，**无需训练** |
| **乐谱唱歌**（YingMusic-Singer）| 乐谱 + 歌词 + 音色 → 生成新歌 | 零样本歌声合成，**不需要现成人声** |

支持**完整歌曲**处理：自动分离人声/伴奏 → 转换 → 混音回伴奏，输出成品。

![界面截图](docs/images/ui.png)

> ⚠️ **仅供个人学习研究使用。** 声音权益受《民法典》第 1023 条保护，请勿克隆未获授权的他人声音。详见 [许可证与合规](#许可证与合规)。

## 功能

### 🎤 音色转换
- 零样本音色克隆：10~30 秒参考音频，无需训练
- **完整歌曲模式**：自动 Demucs 分离人声与伴奏 → 转换 → 混音成成品
- **参考音频分离**：参考是带伴奏的歌曲片段时，可先分离出干声（勾选后即时试听）
- **分离结果试听与按需保存**：分离产物默认只进临时目录，满意再手动保存
- 实时进度：已用时 / 预计总长 / 分段进度

### 🎼 乐谱唱歌
- 输入 **MIDI 乐谱 + 歌词 + 5~7 秒音色音频** → 输出歌声
- **突破单次时长上限**：自动按乐句间隙分段生成，采样级精确拼接，支持整首歌
- 与音色转换**显存互斥调度**：切换模式时自动装卸模型

## 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10/11** | 目前仅在 Windows 验证 |
| 显卡 | **NVIDIA，≥4 GB 显存** | 实测 4 GB 可跑通（见下方实测数据）|
| 显存建议 | 8 GB 更舒适 | 4 GB 下需依赖驱动内存回退，会明显变慢 |
| 磁盘 | **约 20 GB** | 两个环境 + 权重 + ffmpeg |
| Python | 由脚本自动准备 | 需要 `uv` 或 `python` 3.10+ |
| 网络 | 可访问 ModelScope | 权重从 ModelScope 下载（国内直连快）|

> **没有 NVIDIA 显卡不建议尝试**：CPU 推理约慢 20~50 倍，一首 4 分钟的歌需数小时。

## 安装

```powershell
git clone https://github.com/J-0201/nianshan-ai.git
cd nianshan-ai
.\install.ps1
```

`install.ps1` 会自动完成：

1. 拉取上游项目（**固定到已验证的提交号**）
2. 创建两个独立 Python 环境并安装依赖
3. 应用本项目对上游的必要补丁（Windows 适配）
4. 下载模型权重（ModelScope）与 ffmpeg
5. 把本项目文件部署到正确位置

预计耗时 20~60 分钟（取决于网速，需下载约 10 GB）。

**自定义目录布局**：安装脚本默认把上游项目克隆到本仓库的**同级目录**。若已自行放置，可用环境变量覆盖：

| 环境变量 | 含义 |
|---|---|
| `NS_SEEDVC_DIR` | Seed-VC 目录 |
| `NS_SVS_DIR` | YingMusic-Singer 目录 |
| `NS_FFMPEG_DIR` | 含 `ffmpeg.exe` 的目录 |
| `NS_DEMO_AUDIO_DIR` | 界面示例音频目录 |

## 使用

```powershell
# 双击，或在 PowerShell 中执行
.\启动念山AI.bat
```

启动后自动打开浏览器：<http://127.0.0.1:7860/>

也可以绕过 bat 直接用命令行：

```powershell
cd seed-vc
.\run_webapp.ps1
```

停止：关闭控制台窗口，或双击 `停止念山AI.bat`。

### 参数要点

| 参数 | 建议 |
|---|---|
| 扩散步数 | **30~50**。实测步数**只影响音质与耗时，不影响音色相似度**（详见下方实测）|
| 自动 F0 调整 | **必须关闭**（歌声转换）。开启会导致歌声与伴奏调性不一致 |
| 完整歌曲 | 源音频带伴奏时勾选，会自动分离 + 混音 |
| 升降调（乐谱唱歌）| 默认 **-1**。实测大幅移调会明显劣化音质，建议只在 -3~+2 内微调 |

## 实测数据

以下均为作者本机（**RTX 3050 Laptop 4 GB**）实测结果，供参考。

### 音色转换

| 场景 | 耗时 | 显存峰值 |
|---|---|---|
| 8 秒音频，30 步 | 10.5 秒 | 2386 MiB |
| 20.8 秒音频，30 步 | 约 60 秒（RTF 1.69）| 3907 MiB |
| 4 分钟歌曲（分离+转换+混音）| 约 10.5 分钟 | 约 3.9 GB |

### 扩散步数对音色相似度的影响【实测】

用 Seed-VC 自身的 CAM++ 说话人模型测量输出与参考的音色相似度：

| 步数 | 耗时 | 音色相似度 | 8kHz+ 高频能量 |
|---|---|---|---|
| 8 | 6.1 s | 0.6328 | 3.58%（有噪声）|
| 15 | 6.2 s | 0.6645 | 3.75%（有噪声）|
| 30 | 8.2 s | 0.6234 | 1.90% |
| 50 | 12.4 s | 0.6611 | 2.16% |
| 80 | 16.8 s | 0.6668 | **1.73%（≈参考音频）** |

**结论：加步数不会让音色更像，只会减少高频伪影。** 真正影响相似度的是参考音频质量与训练数据，不是步数。

### 乐谱唱歌

| 场景 | 结果 |
|---|---|
| 28 秒乐谱，NFE 32 | 50.3 秒，RTF 1.80 |
| **111 秒乐谱（4 段拼接）** | 198.8 秒，全卡峰值 3910 MiB |
| 音高跟随乐谱 | 轮廓相关系数 0.868（残差 1.79 半音）|
| **拼接点 ±5ms 内最大跳变** | **0.0000（完全无缝）** |
| 单段时长上限 | 40 秒可行，55 秒 OOM |

```
nianshan-ai/
├── install.ps1              一键部署脚本
├── app/                     音色转换应用层
│   ├── app_nianshan.py       念山AI 主界面（Gradio）

├── svs/                     乐谱唱歌
│   ├── long_song.py          分段生成 + 无缝拼接核心
│   ├── svs_runner.py         子进程运行器（JSON 协议）
│   └── verify_melody.py      音准客观验证

```

**本仓库不包含上游代码和模型权重**，两者均由 `install.ps1` 从原始来源获取。

## 已知限制

1. **4 GB 显存非常紧张**：乐谱唱歌会超出物理显存，依赖 NVIDIA 驱动的内存回退（sysmem fallback）才能跑完，代价是速度。此时**不能与其他占显存的程序同时运行**。
2. **两个引擎不能同时驻留**：应用已实现自动装卸，但切换时有约 20 秒的模型加载等待。
3. **乐谱唱歌单次上限约 40~160 秒**（取决于显存），更长的歌靠分段拼接实现。
4. **Windows Only**：macOS（Apple Silicon MPS）与 Linux 均未验证。
5. **音质上限受参考音频制约**：干净、无伴奏、5~30 秒的参考效果最好。
